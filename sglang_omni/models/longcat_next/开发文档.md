# LongCat-Next on sglang-omni 开发文档

## 概述

LongCat-Next 是美团 LongCat 团队发布的原生多模态离散 token 模型（DiNA 范式），
将文本、图像、音频统一为离散 token，由单一 AR backbone 做 Next Token Prediction。

sglang-omni 按阶段接入：
- **Phase 1**（当前）：纯文本 AR backbone 启动

关键架构事实：LongCat-Next 的 `LongcatNextForCausalLM` 继承自
`LongcatFlashForCausalLM`，底层 Transformer（MLA + MoE）与 SGLang 原生支持的
LongCat-Flash 完全一致，仅维度不同。

---

## Phase 1：纯文本 AR Backbone

### 目标

从完整 LongCat-Next checkpoint 中启动 AR backbone，提供标准 chat/completions API。

### 架构参数

| 参数 | 值 |
|---|---|
| 总参数量 | ~68.5B（A3B MoE，激活 ~3B/token） |
| hidden_size | 3072 |
| 层数 | 14（每层：2× MLA + 2× Dense MLP + 1× MoE） |
| 注意力 | MLA（kv_lora_rank=512, q_lora_rank=1536） |
| MoE | 256 routed + 128 zero experts，top-12 |
| 上下文长度 | 131072 |
| text_vocab_size | 131072 |
| 完整词表 | 131125（含 53 个多模态特殊 token） |

### 权重加载策略

完整 checkpoint 约 140GB，各组件按前缀分布：

```
checkpoint 所有权重
├── model.layers.*              → AR backbone，SGLang 直接加载
├── model.embed_tokens.weight   → [131072, 3072]，正常加载
├── model.norm.*                → 正常加载
├── model.ngram_embeddings.*    → SGLang NgramEmbedding 原生支持
├── lm_head.weight              → [131125, 3072]，自定义 head 加载
├── model.visual_tokenizer.*    → Phase 1 过滤（load_weights 中 skip）
├── model.audio_tokenizer.*     → Phase 1 过滤
├── visual_head.*               → Phase 1 过滤
└── audio_head.*                → Phase 1 过滤
```

**不做权重抽取**——各 Phase 按需从同一 checkpoint 加载各自组件。

### 关键适配：词表不对称

LongCat-Next 的 embed_tokens 和 lm_head 词表大小不同：

| 参数 | 行数 | 原因 |
|---|---|---|
| `model.embed_tokens` | 131072 | 输入只有文本 token；多模态占位符在 embedding 前被 visual/audio features 替换 |
| `lm_head` | 131125 | 输出需覆盖文本+视觉+音频全部 token |

SGLang 父类用同一个 `config.vocab_size` 创建两者。`LongcatNextTextForCausalLM`
在 `super().__init__()` 前设 `config.vocab_size = 131072`（控制 embed_tokens），
之后替换 `self.lm_head` 为 131125 行的 head。`_tied_weights_keys = []` 禁用了
权重绑定（形状不同，无法绑定）。

### 关键适配：load_weights

参照官方 `NmmFlashForCausalLM.load_weights`（`modules/nmm_flash.py`）：

1. 过滤多模态前缀（`audio_head.`、`visual_head.`、`model.audio_tokenizer.`、
   `model.visual_tokenizer.`、`model.audio_embed_layers.`）
2. 对 `model.embed_tokens.weight` 和 `lm_head.weight` 做防御性 `[:131125]` 截断
3. 其余委托父类处理（MLA fused QKV、MoE stacked/expert mapping、ngram embeddings）

### Ngram Embedding

SGLang 的 `NgramEmbedding.load_weight` 原生支持 `model.ngram_embeddings.embedders.*`
命名，且 SGLang `LongcatFlashConfig` 与 LongCat-Next HF config 使用相同的字段名
（`ngram_vocab_size_ratio`/`emb_neighbor_num`/`emb_split_num`），应开箱即用。
`__init__` 中保留了 fallback：若 `ngram_embedding_{m,k,n}` 缺失，自动降级为
标准 `VocabParallelEmbedding`。

### 多模态 token 抑制

纯文本推理时，通过 `req._codec_suppress_tokens` 将 token 131072–131124 的
logits 置为 `-inf`，防止模型输出视觉/音频 token。

### 当前限制

- 仅文本生成，无视觉/音频输入输出
- Ngram embedding 兼容性待运行时验证

问题 1：Config 字段名不兼容 → intermediate_size 为 None
LongCat-Next 用 ffn_hidden_size，SGLang 读的是 intermediate_size。导致 gate_up_proj 权重维度错误。

修复：已在 config 映射块做 intermediate_size ← ffn_hidden_size。

问题 2：kv_a_proj_with_mqa 在 checkpoint 中不存在 → attention 权重随机初始化
LongCat-Next checkpoint 的 attention 权重只有 q_a_proj、q_b_proj、kv_b_proj、o_proj。SGLang 在 q_lora_rank is not None 时触发 Q/KV 融合逻辑，等待 q_a_proj + kv_a_proj_with_mqa 同时出现才写入 fused_qkv_a_proj_with_mqa。kv_a_proj_with_mqa 不可能出现→ q_a_proj 被缓存后丢弃→ fused_qkv_a_proj_with_mqa 始终是随机值→ attention 输出垃圾→传到 MLP → CUBLAS 炸。

修复：在 load_weights 中拦截 q_a_proj 权重，手动写入 fused_qkv_a_proj_with_mqa 的前 1536 行。

这两个修复合起来应该能解决 CUBLAS 错误。commit 后重新测试。
